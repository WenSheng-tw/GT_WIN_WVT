get-tw 使用說明

1. 這是什麼

get-tw 讓 Harbour 程式的 @ … SAY … GET、READ 能正確顯示和編輯繁體中文，CP950（Big5）和 UTF-8 都適用：

  • 一個中文字在畫面上佔 2 格，不會被切成半個字。
  • 游標一次跳過一整個中文字；倒退鍵和 Del 一次刪掉整個字；插入、覆寫都以整字為單位。
  • GET 可以用 nMaxChars 限制最多輸入幾個字（見第 5 節）。
  • Alert 對話框依中文寬度排版。

它包括修改過的 GET 類別（tget.prg）、修改過的 AChoice、TBrowse、MemoEdit（achoice.prg、tbrowse.prg、teditor.prg、mlcfunc.c，取代 Harbour 內建的版本，讓它們也依中文寬度排版），以及兩個修改過的畫面層（Harbour 叫 GT，負責把字畫到螢幕上）：

  • WIN_TW：主控台（文字視窗）版，由 Harbour 原版 GTWIN 修改而來。
  • WVT_TW：獨立視窗（GUI）版，由 Harbour 原版 GTWVT 修改而來。

3. 編譯與連結

需要：Harbour 3.2（harbour-core）的 hbmk2，以及 Windows C 編譯器。附的示範程式是用 32 位元 Embarcadero BCC 7.4 編的；也試過用 Visual Studio 2019 的 MSVC 編 32 位元與 64 位元版；其他編譯器沒有試過。

在自己的 .hbp 裡列出（主控台版）：

-winuni
-workdir=work\myprog
-omyprog
-cflag=-utf-8{msvc|msvc64}
# 有用到 CT 視窗（WOpen 等）才需要
hbct.hbc
myprog.prg
..\get-tw\src\tget.prg
..\get-tw\src\gtwin_tw.c
..\get-tw\src\twdisp.prg
..\get-tw\src\achoice.prg
..\get-tw\src\tbrowse.prg
..\get-tw\src\teditor.prg
..\get-tw\src\mlcfunc.c
..\get-tw\src\twambig.c

視窗版改成列 gtwvt_tw.c，並加上 -gui：

-winuni
-gui
-workdir=work\myprog
-omyprog
-cflag=-utf-8{msvc|msvc64}
myprog.prg

..\get-tw\src\gtwvt_tw.c
..\get-tw\src\twdisp.prg

..\get-tw\src\tbrowse.prg

編譯指令：在 .hbp 所在的資料夾執行，下面三種編譯器擇一。

BCC 32 位元

Embarcadero BCC 7.4（32 位元）要在 PATH 上，並使用 BCC 版 Harbour 的 hbmk2（Harbour 的 bin\win\bcc\）：

hbmk2 -comp=bcc -plat=win myprog.hbp

MSVC 32 位元

先在同一個命令提示字元裡執行 Visual Studio 的 vcvars32.bat（或直接開「x86 Native Tools Command Prompt」），再使用 MSVC 版 Harbour 的 hbmk2（Harbour 的 bin\win\msvc\）：

call "<Visual Studio 安裝資料夾>\VC\Auxiliary\Build\vcvars32.bat"
hbmk2 -comp=msvc -plat=win myprog.hbp

MSVC 64 位元

先執行 vcvars64.bat（或直接開「x64 Native Tools Command Prompt」），再使用 MSVC 64 位元版 Harbour 的 hbmk2（Harbour 的 bin\win\msvc64\）：

call "<Visual Studio 安裝資料夾>\VC\Auxiliary\Build\vcvars64.bat"
hbmk2 -comp=msvc64 -plat=win myprog.hbp

用 MSVC 編出的 exe 不需要另外安裝或附帶 DLL：C 執行階段是靜態連結的，只用到 Windows 內建的系統 DLL。

  • -comp=… -plat=win 建議寫在命令列，不要只寫在 .hbp 裡；hbmk2 要用和編譯器對應的那一份 Harbour（bin\win\bcc\、bin\win\msvc\、bin\win\msvc64\）。
  • get-tw 的原始碼是 UTF-8。用 MSVC 時請在 .hbp 加 -cflag=-utf-8{msvc|msvc64}（示範的 .hbp 都有）；只寫 {msvc} 不會套用到 -comp=msvc64。BCC 不要加。
  • 同一份 .hbp 給多種編譯器用時，-workdir 可以寫成 work\${hb_comp}\myprog，各編譯器的中間檔就會分開放（示範的 .hbp 就是這樣寫）。
  • 先自己建好 -workdir 指定的資料夾。有些版本的 hbmk2 不會自動建立，會報錯停止。
  • twwide.c、twwide.h、twambig.h 不要列；twambig.c 要列。上面範例裡的 8 個 get-tw 原始檔要一起列：少了 twambig.c，連結時會出現找不到 TWCODEPOINTCELLS 的錯誤。
  • 不要用 hbmk2 的 -gt 參數指定這兩個畫面層（例如 -gtwin_tw）。hbmk2 會另外去連結一個叫 gtwin_tw 的程式庫；本套件是直接編原始檔，沒有這個程式庫，連結會失敗。請照下一節在程式裡寫 REQUEST。
  • 重編示範程式時，exe 會寫到 test\（Release zip 的 test\ 裡沒有 exe，編好的示範 exe 在 bin\ 底下）。

編示範程式：在 test\ 資料夾裡先建好 work\bcc\demo_gtwin、work\bcc\demo_gtwvt 兩個資料夾，再執行（.hbp 裡的路徑都是相對於 test\）。以下以 BCC 為例；用 MSVC 時先呼叫 vcvars，並把 bcc 換成 msvc 或 msvc64，中間檔就會放在 work\msvc\、work\msvc64\：

cd test
mkdir work\bcc\demo_gtwin work\bcc\demo_gtwvt
hbmk2 -comp=bcc -plat=win demo_gtwin.hbp
hbmk2 -comp=bcc -plat=win demo_gtwvt.hbp
  • 視窗版的 demo_gtwvt.hbp 已經有 -gui。

4. 在自己的程式加 REQUEST

在任一個 .prg 檔的最外層（不在任何 FUNCTION／PROCEDURE 裡）加上一行，讓程式開機時用這個畫面層：

REQUEST HB_GT_WIN_TW_DEFAULT     // 主控台版
// 或
REQUEST HB_GT_WVT_TW_DEFAULT     // 視窗版

用 CP950 時另外加 REQUEST HB_CODEPAGE_CP950（UTF-8 內建，不用加），並在程式開頭選好碼頁。示範程式的寫法是：

hb_cdpSelect( "CP950" )            // 或 "UTF8"
hb_cdpIsCharIdx( "CP950", .T. )    // 開字元索引（示範程式兩種碼頁都開）

示範程式只在「字元索引開」的設定下操作過，建議照做；關閉時的行為見第 8 節。

其他說明：

  • 畫面層名稱不分大小寫。若要從命令列改用某個畫面層，寫 //GTWIN_TW、//GTWVT_TW（也可寫成 //GT:WIN_TW）。也可以設環境變數 HB_GT=WIN_TW。
  • hb_gtVersion() 會回傳目前畫面層的名稱 "WIN_TW" 或 "WVT_TW"，可以拿來確認程式實際用的是哪一個畫面層；示範程式畫面第一列的 GT= 就是顯示它。
  • 舊名稱 TW 開頭的畫面層與舊的 REQUEST 寫法已經不存在；先前用舊名的程式要改成上面的新寫法。
  • 視窗版需要能顯示繁體中文的字型。示範程式的視窗版設定細明體： 
    hb_gtInfo( HB_GTI_FONTNAME, "MingLiU" )   // 需 #include "hbgtinfo.ch"
  • 以西歐語文為主的程式，應呼叫 TwAmbigW(1)，或設定環境變數 GETTW_AMBIGW（例如 GETTW_AMBIGW=1），讓寬度會隨語境改變的字元按 1 格計算。預設為 2 格，適合中文排版。

5. nMaxChars：限制最多輸入幾個字

nMaxChars 是 Get 物件上的一個屬性，預設是 NIL（不限制）。沒有對應的 @…GET 子句，要在 GET 建立後，直接設定 GetList 裡那個 Get 物件。

計算單位

  • UTF-8：算字數（一個中文字算 1）。
  • CP950：算位元組（一個中文字算 2，英數字算 1）。
  • NIL、0、負數或不是數字：不限制（和原版行為一樣）。有小數時取整數。

實際上限與適用範圍

  • 游標進入欄位時，實際上限 ＝ nMaxChars 與欄位寬度兩者取小的。欄位寬度同樣是 UTF-8 算字數、CP950 算位元組。
  • 只對字元型欄位有效，而且 PICTURE 的遮罩只能由 ! A N X 9 # 組成（例如 Replicate( "X", 10 )、"@!"）。遮罩裡夾其他固定字元的欄位不套用。
  • 打滿上限後就不能再往後輸入；游標最遠停在上限處。
  • 內容有改過時，離開欄位寫回變數前會整字截到上限（不會切半個中文字），再用空白補回欄寬。程式直接寫入、沒有經過編輯的內容不會被截。
  • 初值本來就超過上限時，不會先砍掉，使用者可以用倒退鍵刪到上限內。
  • nMaxChars 本身會保留，下次進入欄位重新計算上限。

單一欄位

示範程式的寫法：GET 一建立就是 GetList 的最後一個，用 ATail( GetList ) 取到它：

LOCAL cMax := Space( 10 )
@ 6, 2 SAY "備註" GET cMax PICTURE Replicate( "X", 10 )
ATail( GetList ):nMaxChars := 6
READ

多個欄位：用迴圈設定

先照平常寫法建好所有 GET，在 READ 之前用迴圈依序設定 GetList 裡每個 Get 物件的 nMaxChars：

LOCAL cName := Space( 10 )
LOCAL cAddr := Space( 20 )
LOCAL cCode := Space( 8 )
LOCAL aMax  := { 4, 10, NIL }       // 依 GET 的順序；NIL＝不限制
LOCAL i

@ 4, 2 SAY "姓名" GET cName PICTURE Replicate( "X", 10 )
@ 6, 2 SAY "地址" GET cAddr PICTURE Replicate( "X", 20 )
@ 8, 2 SAY "代號" GET cCode PICTURE "@!"

FOR i := 1 TO Len( GetList )
   GetList[ i ]:nMaxChars := aMax[ i ]
NEXT
READ

GetList 裡的順序就是 @…GET 寫的順序。若畫面上還有其他不需要限制的 GET，aMax 對應的位置填 NIL 即可。

6. 執行示範程式

Release zip 的 bin\ 底下有三組編好的示範程式：bin\win32-bcc\（BCC 32 位元）、bin\win32-msvc\（MSVC 32 位元）、bin\win64-msvc\（MSVC 64 位元，需要 64 位元 Windows）。每組資料夾都有 2 個 exe 和同樣的 4 個批次檔，雙擊批次檔即可。每個批次檔都會先切到自己所在的資料夾，再用指定的碼頁執行同一資料夾裡的 exe：

批次檔畫面層碼頁
demo_gtwin_utf8.bat主控台 WIN_TWUTF-8
demo_gtwin_cp950.bat主控台 WIN_TWCP950（Big5）
demo_gtwvt_utf8.bat視窗 WVT_TWUTF-8
demo_gtwvt_cp950.bat視窗 WVT_TWCP950（Big5）
  • 畫面第一列會顯示 GT= 目前畫面層名稱（WIN_TW 或 WVT_TW）、碼頁、CONFIRM 設定。
  • 表單有：中文標籤的欄位、限制 6 個字的欄位（nMaxChars＝6）、只收英數的欄位、日期、數字。之後示範 SaveScreen／RestScreen，最後在 CT 視窗裡再做一個 GET。
  • CONFIRM 預設關；要試開啟，把批次檔最後一個參數 OFF 改成 ON。
  • 用平常的中文輸入法輸入即可。
  • exe 也可以自己帶參數執行：demo_gtwin.exe <CP950|UTF8> <ON|OFF>。第三個參數 AUTO 是自動按鍵的自我測試用，平常不用。

7. 已知限制

  • 不可搭配原版 GTWIN／GTWVT。中文寬字的處理放在 WIN_TW／WVT_TW 裡面；修改過的 GET 依賴它們。如果程式沒有 REQUEST 本套件的畫面層，或用命令列、環境變數切到原版 GTWIN／GTWVT，原版不會有這些處理，中文會顯示或編輯錯誤（例如半個字、殘字、錯位）。請務必照第 4 節 REQUEST。
  • DispBox 用中文字當填滿字元：不支援，顯示不正確。
  • TBrowse、AChoice、MemoEdit 的中文寬度：v1.0.1 起改用顯示寬度計算（TBrowse 的欄位內容、欄寬、標題與註腳，AChoice 的選項，MemoEdit 的斷行），中文不會再被截短或切在字中間。只有最右邊露出一部分的 TBrowse 欄位，仍是依字數截斷，可能超出或少一格（未測試）。
  • UTF-8 字碼 0x20000 以上的字（多為罕用字）：畫面每格只存 16 位元，顯示不出來。
  • 熱鍵會提早截字：欄位改過之後按任何熱鍵（SetKey），內容會先截到上限，不等離開欄位。這是 Harbour READ 本來的流程。
  • CT 視窗裡的 Alert 走 hbct 自己的程式，仍按字數量寬，沒有依中文寬度排版。
  • 資料含 BIG5 專有字時，請用 hb_cdpSelect("BIG5") 或 UTF-8，不要用 CP950。
  • 補完計畫（UAO）中對應到 Unicode 私人造字區（PUA）的字，畫面顯示取決於所用字型與各電腦的造字檔（EUDC），不同電腦可能顯示不同字形或空白，屬已知限制。
  • 執行時若設定 CODEPAGE=255，視窗會改用 Terminal 字型。
  • 調整視窗大小：視窗版（WVT_TW）拖曳改變視窗大小時，畫面的列數與欄數不變，文字會跟著視窗放大或縮小。主控台版（WIN_TW）在程式執行中改變主控台或 Windows Terminal 的視窗大小時，Windows 會把畫面上的文字重新折行，並可能捲動畫面，程式畫面會錯位，游標也會和文字對不上。之後程式只更新有變動的部分，所以按方向鍵等一般操作不會讓畫面恢復；只有程式把整個畫面重畫時才可能恢復，最穩妥的做法是結束程式後重新執行。程式若在收到 HB_K_RESIZE（視窗大小改變的通知）時把整個畫面重畫，畫面與游標可以恢復；這需要把事件遮罩加上 HB_INKEY_GTEVENT，例如 Set( _SET_EVENTMASK, hb_bitOr( INKEY_ALL, HB_INKEY_GTEVENT ) )（需 #include "inkey.ch"）。MemoEdit、AChoice、TBrowse 本身不會這樣重畫。請不要在程式執行時調整主控台視窗大小。
  • Windows Terminal（WT）：主控台版（WIN_TW）在 Windows Terminal 1.24 執行時，Windows Terminal 會把寬度不一定的符號（例如 € ○ ※ × ° 和框線符號）畫成 1 格，get-tw 則依中文排版算成 2 格，所以同一行這類符號後面的文字和反白條會錯位。一般中文字不受影響。遇到這種情形，請改用傳統主控台視窗（conhost）或視窗版（WVT_TW）。Windows Terminal 1.25 的 ambiguousWidth 設定可能有幫助，但尚未測試。

8. 尚未驗證的項目

以下項目目前沒有在最新版本上實際驗證，請使用時自行留意：

  • GET 欄位在畫面被其他內容蓋過、再重畫回來時的樣子。
  • CP950、字元索引關閉時，欄位有字數上限、編輯後按 End、Del 或功能鍵（熱鍵）觸發截字，畫面重畫後中文字是否完整。字元索引關閉時還有多項行為差異尚未逐一查明。
  • 用 QOut、?、QQOut 輸出中文（包括寫到最右欄自動換行），以及用 Replicate 畫中文。
  • SaveScreen／RestScreen 存回含中文的整個畫面或部分區域（區域邊界切過中文字時），還原後中文是否完整、邊界的半個字是否變成空白。
  • 視窗版用細明體時，單線、雙線方框的框線是否連續（包括視窗縮到最小再還原後）。
  • 同一支程式同時連結兩個畫面層，執行時互相切換。
  • 在 CT 視窗疊在上面時，畫面輸出是否正確判斷中文的前半／後半。
  • 視窗版用滑鼠拖曳選取含中文的區域並複製，剪貼簿內容是否不會重複出現中文字。
  • 非全螢幕情況下的 Alert，以及 CT 視窗裡的 Alert。
  • DispBegin 包住的 READ、只改顏色的重畫、畫面閃爍。
  • 切回原版 GTWIN／GTWVT 時的實際畫面。
  • BCC 7.4 以外的編譯器（MSVC 32／64 位元目前只試過編譯與開啟畫面）。

中文輸入法輸入：負責人親自試過正常。
