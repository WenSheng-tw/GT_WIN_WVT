get-tw User Guide

1. What it is

get-tw makes Harbour @ … SAY … GET and READ display and edit Traditional Chinese text correctly, in both CP950 (Big5) and UTF-8:

  • Each Chinese character occupies two screen cells and is never split in half.
  • The cursor moves over a whole Chinese character; Backspace and Del remove a whole character; insert and overwrite work on whole characters.
  • A GET can limit how many characters may be typed, with nMaxChars (section 5).
  • Alert dialogs are laid out by Chinese display width.

It contains a modified GET class (tget.prg), modified AChoice, TBrowse and MemoEdit (achoice.prg, tbrowse.prg, teditor.prg, mlcfunc.c; they replace Harbour's built-in versions so that these also lay out text by Chinese width), and two modified terminal drivers (Harbour calls them GTs; they draw text on the screen):

  • WIN_TW – console version, modified from Harbour's GTWIN.
  • WVT_TW – GUI window version, modified from Harbour's GTWVT.

3. Building and linking

Requirements: hbmk2 from Harbour 3.2 (harbour-core) and a Windows C compiler. The included demos were built with 32-bit Embarcadero BCC 7.4; building with MSVC from Visual Studio 2019 (32-bit and 64-bit) has also been tried; other compilers have not been tried.

Add these to your own .hbp (console version):

-winuni
-workdir=work\myprog
-omyprog
-cflag=-utf-8{msvc|msvc64}
# only if you use CT windows (WOpen etc.)
hbct.hbc
myprog.prg
..\get-tw\src\tget.prg
..\get-tw\src\gtwin_tw.c
..\get-tw\src\twdisp.prg
..\get-tw\src\achoice.prg
..\get-tw\src\tbrowse.prg
..\get-tw\src\teditor.prg
..\get-tw\src\mlcfunc.c
..\get-tw\src\twambig.c

For the GUI version list gtwvt_tw.c instead and add -gui:

-winuni
-gui
-workdir=work\myprog
-omyprog
-cflag=-utf-8{msvc|msvc64}
myprog.prg
..\get-tw\src\tget.prg
..\get-tw\src\gtwvt_tw.c
..\get-tw\src\twdisp.prg
..\get-tw\src\achoice.prg
..\get-tw\src\tbrowse.prg
..\get-tw\src\teditor.prg
..\get-tw\src\mlcfunc.c
..\get-tw\src\twambig.c

Build command: run hbmk2 in the folder of the .hbp, with one of the three compilers below.

BCC 32-bit

Embarcadero BCC 7.4 (32-bit) must be on the PATH; use hbmk2 from the BCC build of Harbour (Harbour's bin\win\bcc\):

hbmk2 -comp=bcc -plat=win myprog.hbp

MSVC 32-bit

First run Visual Studio's vcvars32.bat in the same command prompt (or open the "x86 Native Tools Command Prompt"), then use hbmk2 from the MSVC build of Harbour (Harbour's bin\win\msvc\):

call "<Visual Studio install folder>\VC\Auxiliary\Build\vcvars32.bat"
hbmk2 -comp=msvc -plat=win myprog.hbp

MSVC 64-bit

First run vcvars64.bat (or open the "x64 Native Tools Command Prompt"), then use hbmk2 from the 64-bit MSVC build of Harbour (Harbour's bin\win\msvc64\):

call "<Visual Studio install folder>\VC\Auxiliary\Build\vcvars64.bat"
hbmk2 -comp=msvc64 -plat=win myprog.hbp

Executables built with MSVC need no extra DLL to be installed or shipped: the C runtime is linked statically, and only the system DLLs that come with Windows are used.

  • Put -comp=… -plat=win on the command line rather than only in the .hbp, and use the Harbour build that matches the compiler (bin\win\bcc\, bin\win\msvc\, bin\win\msvc64\).
  • The get-tw sources are UTF-8. With MSVC, add -cflag=-utf-8{msvc|msvc64} to the .hbp (both demo .hbp files do); {msvc} alone does not apply to -comp=msvc64. Do not pass it to BCC.
  • If one .hbp is used with several compilers, -workdir can be written as work\${hb_comp}\myprog so that each compiler keeps its intermediate files apart (the demo .hbp files do this).
  • Create the -workdir folder yourself first. Some hbmk2 versions do not create it and stop with an error.
  • Do not list twwide.c, twwide.h or twambig.h; do list twambig.c. List all eight get-tw source files from the examples above: without twambig.c, linking fails with an unresolved TWCODEPOINTCELLS.
  • Do not use hbmk2's -gt option for these drivers (e.g. -gtwin_tw). hbmk2 would also try to link a library called gtwin_tw; get-tw is compiled from source and provides no such library, so linking fails. Use the REQUEST line from section 4 instead.
  • Rebuilding the demos writes the exes to test\ (the Release zip has no exes in test\; the prebuilt demo exes are under bin\).

To build the demos: in the test\ folder create work\bcc\demo_gtwin and work\bcc\demo_gtwvt first, then run (all paths in the .hbp files are relative to test\). The example uses BCC; for MSVC, call vcvars first and replace bcc with msvc or msvc64, and the intermediate files go to work\msvc\ or work\msvc64\:

cd test
mkdir work\bcc\demo_gtwin work\bcc\demo_gtwvt
hbmk2 -comp=bcc -plat=win demo_gtwin.hbp
hbmk2 -comp=bcc -plat=win demo_gtwvt.hbp
  • demo_gtwvt.hbp for the GUI version already contains -gui.

4. Adding the REQUEST to your program

Put one of these lines at module level (outside any FUNCTION / PROCEDURE) in one of your .prg files, so the program starts with this driver:

REQUEST HB_GT_WIN_TW_DEFAULT     // console
// or
REQUEST HB_GT_WVT_TW_DEFAULT     // GUI window

For CP950 also add REQUEST HB_CODEPAGE_CP950 (UTF-8 is built in) and select the codepage at startup. The demos do this:

hb_cdpSelect( "CP950" )            // or "UTF8"
hb_cdpIsCharIdx( "CP950", .T. )    // character indexing on (the demos turn it on for both codepages)

The demos have only been exercised with character indexing on, and we suggest you do the same; see section 8 for the off case.

Other notes:

  • Driver names are not case-sensitive. To choose a driver on the command line write //GTWIN_TW or //GTWVT_TW (//GT:WIN_TW also works). The environment variable HB_GT=WIN_TW works too.
  • hb_gtVersion() returns the name of the active driver, "WIN_TW" or "WVT_TW", so you can check which one your program is really using; the GT= value on the demo's top line shows it.
  • The old driver names that began with TW and the old REQUEST lines no longer exist; programs that used them must be changed to the names above.
  • The GUI version needs a font that can show Traditional Chinese. The GUI demo sets MingLiU: 
    hb_gtInfo( HB_GTI_FONTNAME, "MingLiU" )   // needs #include "hbgtinfo.ch"
  • Programs that consist mainly of Western-European text should call TwAmbigW(1) or set the GETTW_AMBIGW environment variable (for example GETTW_AMBIGW=1), so that ambiguous-width characters are counted as 1 cell. The default is 2 cells, which suits Chinese layout.

5. nMaxChars: limiting how many characters can be typed

nMaxChars is a property of the Get object; the default is NIL (no limit). There is no @…GET clause for it; set it on the Get object in GetList after the GET has been created.

Unit

  • UTF-8: counts characters (one Chinese character = 1).
  • CP950: counts bytes (one Chinese character = 2, a letter or digit = 1).
  • NIL, 0, a negative number or a non-numeric value: no limit (original behavior). Decimals are truncated to an integer.

Effective limit and scope

  • When the field receives focus, the effective limit is the smaller of nMaxChars and the field width (field width is also characters in UTF-8, bytes in CP950).
  • Applies only to character fields whose PICTURE mask uses only ! A N X 9 # (e.g. Replicate( "X", 10 ), "@!"). Fields whose mask contains other literal characters are not limited.
  • Once the limit is reached no more can be typed; the cursor stops at the limit.
  • If the content was edited, it is cut to the limit on whole characters (never half a Chinese character) before being written back, then padded with spaces to the field width. Values written by the program without editing are not cut.
  • If the initial value is already over the limit it is not cut in advance; the user can Backspace it down.
  • nMaxChars itself is kept; the limit is recalculated each time the field gets focus.

One field

As in the demo: a new GET is the last element of GetList, so use ATail( GetList ):

LOCAL cMax := Space( 10 )
@ 6, 2 SAY "Note" GET cMax PICTURE Replicate( "X", 10 )
ATail( GetList ):nMaxChars := 6
READ

Several fields: set them in a loop

Create all GETs as usual, then before READ loop over GetList and set nMaxChars on each Get object:

LOCAL cName := Space( 10 )
LOCAL cAddr := Space( 20 )
LOCAL cCode := Space( 8 )
LOCAL aMax  := { 4, 10, NIL }       // in GET order; NIL = no limit
LOCAL i

@ 4, 2 SAY "Name"    GET cName PICTURE Replicate( "X", 10 )
@ 6, 2 SAY "Address" GET cAddr PICTURE Replicate( "X", 20 )
@ 8, 2 SAY "Code"    GET cCode PICTURE "@!"

FOR i := 1 TO Len( GetList )
   GetList[ i ]:nMaxChars := aMax[ i ]
NEXT
READ

GetList is in the order the @…GET lines were written. Use NIL in aMax for GETs that should not be limited.

6. Running the demos

The bin\ folder of the Release zip contains three prebuilt sets: bin\win32-bcc\ (BCC 32-bit), bin\win32-msvc\ (MSVC 32-bit) and bin\win64-msvc\ (MSVC 64-bit, needs 64-bit Windows). Each folder has the two exes and the same four .bat files; double-click one. Each changes to its own folder and runs the exe in that folder with the given codepage:

ScriptDriverCodepage
demo_gtwin_utf8.batconsole WIN_TWUTF-8
demo_gtwin_cp950.batconsole WIN_TWCP950 (Big5)
demo_gtwvt_utf8.batGUI WVT_TWUTF-8
demo_gtwvt_cp950.batGUI WVT_TWCP950 (Big5)
  • The first screen line shows GT= with the active driver name (WIN_TW or WVT_TW), the codepage and the CONFIRM setting.
  • The form has a field with a Chinese label, a field limited to 6 (nMaxChars = 6), a letters-and-digits field, a date and a number; then SaveScreen / RestScreen, and finally a GET inside a CT window.
  • CONFIRM is OFF by default; to try ON, change the last argument in the .bat from OFF to ON.
  • Type Chinese with your normal input method.
  • You can also run the exe yourself: demo_gtwin.exe <CP950|UTF8> <ON|OFF>. A third argument AUTO is an automatic key self-test and is not needed normally.

7. Known limitations

  • Cannot be used with the original GTWIN / GTWVT. The wide-character handling lives inside WIN_TW / WVT_TW, and the modified GET depends on it. If your program does not REQUEST one of these drivers, or the command line / environment switches to the original GTWIN or GTWVT, none of this handling is present and Chinese text will be shown or edited incorrectly (half characters, leftover characters, misalignment). Always add the REQUEST from section 4.
  • DispBox filled with a Chinese character is not supported and does not display correctly.
  • Chinese width in TBrowse, AChoice and MemoEdit: since v1.0.1 these count display width (TBrowse cells, column widths, headings and footings; AChoice items; MemoEdit line wrapping), so Chinese text is no longer cut short or split in the middle of a character. Only a rightmost TBrowse column that is partly visible is still cut by character count, so it may run one cell too far or stop one cell short (not tested).
  • UTF-8 characters at code point 0x20000 and above (mostly rare characters) cannot be displayed, because each screen cell stores only 16 bits.
  • Hot keys cut early: after a field has been edited, pressing any hot key (SetKey) cuts the content to the limit straight away, without waiting for the field to be left. This is how Harbour's READ works.
  • Alert inside a CT window uses hbct's own code, which still measures by character count, not Chinese width.
  • If your data contains characters that exist only in BIG5, use hb_cdpSelect("BIG5") or UTF-8 instead of CP950.
  • Characters that the UAO extension maps to the Unicode Private Use Area (PUA) are drawn from whatever the active font and the PC's end-user-defined character (EUDC) file provide, so they may look different or appear blank on different PCs. This is a known limitation.
  • Setting CODEPAGE=255 at runtime makes the window fall back to the Terminal font.
  • Resizing the window: In the window build (WVT_TW), dragging the window to a new size keeps the number of rows and columns, and the text scales with the window. In the console build (WIN_TW), resizing the console or Windows Terminal window while a program is running makes Windows rewrap the text on screen and may scroll it, so the program's screen becomes misaligned and the cursor no longer lines up with the text. After that the program only updates the parts that change, so ordinary keys such as the arrow keys do not restore the screen. It can only recover when the program redraws the whole screen; the safest way is to exit the program and run it again. A program that redraws its whole screen when it receives HB_K_RESIZE (the notice that the window size has changed) gets its screen and cursor back in line. For this the event mask must include HB_INKEY_GTEVENT, for example Set( _SET_EVENTMASK, hb_bitOr( INKEY_ALL, HB_INKEY_GTEVENT ) ) (needs #include "inkey.ch"). MemoEdit, AChoice and TBrowse do not redraw this way by themselves. Do not resize the console window while a program is running.
  • Windows Terminal: When the console build (WIN_TW) runs in Windows Terminal 1.24, Windows Terminal draws symbols whose width is ambiguous (for example € ○ ※ × ° and box-drawing characters) one cell wide, while get-tw counts them as two cells for Chinese layout. On a line that contains such symbols, the text after them and the highlight bar are out of place. Ordinary Chinese characters are not affected. In that case, use the classic console window (conhost) or the window build (WVT_TW). The ambiguousWidth setting in Windows Terminal 1.25 may help, but it has not been tested.

8. Not yet verified

The following have not been checked on the current version; please take care:

  • How a GET field looks when it is redrawn after other output has covered it.
  • CP950 with character indexing off: a field with a length limit, edited and then cut by End, Del or a function (hot) key — whether the Chinese text is still complete after the redraw. Several other behavior differences with character indexing off have not been examined case by case.
  • Writing Chinese with QOut, ? and QQOut (including wrapping at the last column), and drawing Chinese with Replicate.
  • SaveScreen / RestScreen of a full screen or a region containing Chinese (including region edges that cut through a character): whether the text is complete after restoring and a half character at the edge becomes blank.
  • GUI version with the MingLiU font: whether single- and double-line box borders are continuous (including after minimize and restore).
  • One program linked with both drivers and switching between them at run time.
  • With a CT window on top, whether screen output still recognizes the two halves of a Chinese character correctly.
  • GUI version: selecting a region with Chinese by mouse drag and copying it — whether the clipboard text is free of duplicated characters.
  • Alert when not full screen, and Alert inside a CT window.
  • READ wrapped in DispBegin, color-only redraws, flicker.
  • The actual screen when switching back to the original GTWIN / GTWVT.
  • Compilers other than BCC 7.4 (MSVC 32-bit and 64-bit have only been tried for building and the start screen).

Chinese input method (IME) input: tested personally by the project owner and worked normally.
